Welcome — let's get your first product live

This guide walks you through ShopifyProductAdd.V2 step by step. No rush. Learn each piece, test one product, then run the full automation.

What this workflow does

Reads a row from Google Sheets → removes background (Photoroom) → AI writes listing → QA scores it → creates a draft product in Shopify with image.

What you need before starting

  • n8n account (cloud or self-hosted)
  • Google Sheet for products
  • Photoroom API key
  • ImgBB API key (free)
  • Shopify trial / dev store
  • OpenAI API (via n8n)

How to use this guide

There are 10 pages. Use Next / Back or the dots at the bottom. Do pages 1–6 before your first real run. Pages 7–9 are for going live. Page 10 is future work.

Golden rule: Run each node one by one the first time. Only turn the workflow Active after one full test passes.

Shopify built-in product CSV template

  1. Log in to your Shopify Admin (trial store is fine).
  2. Go to Products → click Import.
  3. Click Download CSV template — Shopify gives you their full export format with every column.
  4. Open that CSV in Google Sheets (File → Import → Upload).
  5. Rename the tab to product_template — the workflow expects this name.
Do not delete columns blindly. Shopify's template has 40+ columns. Most are for shipping, tax, Google Shopping, variants. Our workflow only uses a handful. Hide what you don't need — don't delete unless you're sure.

Page 4 — Connect everything

4-step credential setup

Do these in order. Each takes about 5–10 minutes. You only do this once (re-do after re-importing the workflow JSON).

1

Google Sheets

  1. n8n → Credentials → New → Google Sheets OAuth2
  2. Sign in with the Google account that owns the sheet
  3. Open Google Sheets Trigger node → select your credential
  4. Pick document product_template and sheet tab
  5. Trigger column: Price
  6. Reconnect same credential on all Update row in sheet nodes
2

Photoroom (background removal)

  1. Get API key from photoroom.com/api
  2. n8n → Credentials → Header Auth
  3. Header name: x-api-key → Value: your key
  4. Open HTTP Request (Photoroom node) → attach credential
3

ImgBB (image hosting)

  1. Free key at api.imgbb.com
  2. Open HTTP Request1 node
  3. Query parameter key → replace REPLACE_IMGBB_KEY
  4. Important: Re-import resets this — fix every time you import JSON
4

Shopify (trial store)

  1. Create free trial at shopify.com
  2. Admin → Settings → Apps → Develop apps → Create app
  3. Scopes: read_products, write_products, read_inventory, write_inventory
  4. Install app → copy Admin API token OR use OAuth in n8n
  5. Connect on: Create a product, Upload image to Shopify, Update price, SKU and image link
  6. Change store URL 8kqexi-2j to YOUR store slug in HTTP nodes
OpenAI: Connect on Analyze image, Message a model, and Message a model1 (QA). n8n Cloud can use built-in OpenAI credentials.

Page 7 — Go live (one product)

Run the full workflow at once

After every node passed individually, you're ready for a real end-to-end run.

Step-by-step

  1. Fill row 2 in Google Sheet — everything except Price.
  2. In n8n, make sure workflow is still Inactive for manual test OR Active for auto trigger.
  3. Enter Price in the sheet (e.g. 29.99).
  4. Wait ~1 minute (trigger polls Price column).
  5. Watch n8n Executions tab — should show full green path.
  6. Check sheet: QA Status, AI Score, Generated Image URL, Shopify URLs.
  7. Check Shopify Admin → Products → your draft product with image.

When to turn workflow Active

Toggle Active only after one full PASS. Then each Price change on a new row auto-runs the workflow.

Batch products (later)

Add many rows with unique SKUs. Enter Price one row at a time. Wait for each run to finish before triggering the next. Safer for credits and debugging.

Page 8 — Human QA (the part people miss)

What happens when QA fails?

Not every run creates a Shopify product. That's intentional — it's your safety net.

QA Status meanings

QA StatusAI ScoreWhat happenedYour action
PASS≥ 90Shopify draft created with imageReview in Shopify, publish when ready
PASS_NO_IMAGE≥ 90Product created but image missing on CDNCheck Upload image node; re-run or add image manually
FAIL< 90No Shopify product. Update QA Failed node ran.Human review required

Human QA checklist (when FAIL)

  1. Open sheet row — read AI Score and check listing columns (Title, Description, SEO fields).
  2. In n8n, open Message a model1 output → find issues array. This tells you what the AI flagged.
  3. Common fixes:
    • Description too vague → add real specs (material, fit, size) in sheet Description
    • AI invented details → tighten Description to facts only
    • Bad image → use a clearer Product image URL
    • Wrong category → fix Product category (plain text, no formula errors)
  4. Clear QA Status and AI Score cells.
  5. Change Price slightly (e.g. 29.99 → 30.00) to re-trigger the whole workflow.
Skip logic: If a row already has PASS and score ≥ 90, the workflow skips it — no duplicate Shopify product. Clear QA fields if you need a full re-run.

Who does human QA?

A team member reviews FAIL rows before re-running. This is not automated — someone reads the issues, fixes the sheet, and triggers again. Think of it as your editorial gate before products go to Shopify.

Page 9 — Debug like a pro

Debugging & making the workflow flawless

Common errors & fixes

ErrorCauseFix
OpenAI URL timeout Analyze image using ImgBB URL Input Type = Binary File, field data from Photoroom
422 corrupt image Bad base64 or JSON.stringify double encoding Use latest JSON. Download node = File format. Upload = JSON object expression
efbfbd in hex (not valid image) Code node downloaded image as UTF-8 text Use Download ImgBB for Shopify HTTP node (File), not Code download
Shopify timeout on src URL Shopify can't fetch i.ibb.co Use attachment upload (Prepare → base64 → Upload JSON)
Product category #ERROR Sheet formula =Casual Wear Type plain text or ="Casual Wear"
Row not updating SKU missing or mismatch Every row needs unique SKU. Match column = SKU on all sheet nodes
ImgBB key missing Re-import reset placeholder Replace REPLACE_IMGBB_KEY in HTTP Request1

Debug workflow (every time something breaks)

  1. n8n → Executions → click the failed run
  2. Find the red node — read full error message
  3. Click node → Input tab — was data missing upstream?
  4. Click node → Output tab — what did it actually return?
  5. For HTTP nodes: check status code, response body
  6. For Code nodes: add console.log() → open browser DevTools (F12) → Console
  7. Fix one node → re-run from that point → don't activate until green end-to-end

Why Upload uses JSON (not Form-Data)

Shopify's images.json API expects JSON: { "image": { "attachment": "base64..." } }. Form-Data is for ImgBB upload. Different APIs, different body types — both are correct for their step.
