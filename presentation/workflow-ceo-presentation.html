System design

End-to-end architecture

Google Sheets Trigger
  ├─ PASS row? → skip (no duplicate)
  ├─ needs scrape? → Route → HTTP | .json | Browserless
  │    → Prepare page → AI scrape → Apply → Update sheet → Re-read formulas
  └─ Active product row (merge scrape + sheet formulas)
      → Has image? → Photoroom → ImgBB → Analyze image
      → AI write listing → Check overlap → AI QA score
      → QA ≥ 90? → Build Shopify product (variants)
      → Create draft → Upload image → Set stock → Collection → Sheet URLs
Design principle: Code extracts first (free, fast). AI fills gaps only. Browserless only for bot-protected domains (~20% of URLs).

Honest assessment

Current limitations

⚠️ Image: One hero image per product. All colors show same photo until ColorImageLibrary ships.
⚠️ Bot protection: Mango, Macy's, Zara need Browserless API token. Without it → NEEDS_BROWSER / partial scrape.
⚠️ Variants: Scrape misses sizes on 40–45% of bot-protected sites. VariantLibrary defaults fill the grid — may not match competitor exactly.
⚠️ Price: Competitor price is reference only. Sell price set in sheet manually — not auto-mapped to Shopify yet.
⚠️ Throughput: ~20 products/hour single-threaded. No parallel batch without engineering.
⚠️ Legal: Scraped images used as input to Photoroom — for internal test store. Public launch needs owned or licensed images.
